# 鼠鼠 Cleaner「鼠鼠的幻想」单页 UI 设计

## 状态

- 设计方向：幻想连环画
- 目标平台：现有 Windows PowerShell/WPF 桌面应用
- 功能权威：本地 `master` 的已加固实现，设计确认时为 `17af146`
- 远端关系：设计确认时本地分支比 `origin/master` 领先 22 个提交；GitHub 仓库仅作为项目基线，不能覆盖本地安全改进
- 范围：重做 GUI 的信息架构、视觉、文案和状态反馈，不重写扫描与清理引擎

## 设计目标

把当前四标签页工具改成一条清晰的单页任务旅程。界面用“专业系统工具与低清鼠鼠幻想表情包的反差”建立辨识度，但所有结论、权限和执行状态必须准确、克制、可审计。

核心原则：

1. 每个阶段对应一种鼠鼠幻想。
2. 幻想负责叙事，技术细节默认折叠。
3. 用户沿单页状态旅程完成扫描、复核、执行和恢复。
4. 保留原梗的对称 P 图与轻微低清质感，不把它改成普通仓鼠、卡通吉祥物或通用贴纸。
5. 视觉改版不得削弱 Schema 3.0 matcher provenance、pending v2、提权复核和目标身份校验。

## 选定视觉构图

页面上部永久保留四格“幻想连环画”：

1. 幻想：电脑轻盈如风。
2. 现实：后台服务持续驻留。
3. 决定：鼠鼠开始谨慎整理。
4. 目标：电脑恢复轻盈状态。

四格不是四个导航标签。它们是同一流程的阶段指示器，会随真实状态逐格点亮。页面下半部是唯一工作区，随状态切换内容和主操作。

每个状态最多有一个黄色主按钮。次要操作使用弱化按钮或文字入口，危险或不可逆操作不得仅靠颜色区分。

## 状态模型与交互

UI 使用以下单向状态模型：

```text
idle -> scanning -> results -> review -> executing -> completed
                    |          |           |
                    +----------+-----------+-> error
```

### Idle：开始幻想

- 展示鼠鼠幻想电脑变轻盈的主视觉。
- 明确说明“扫描只读，不会修改系统”。
- 唯一主操作为“开始安全扫描”。
- 可从弱化入口查看历史记录或恢复能力，但不干扰首次任务。

### Scanning：现实逐渐显现

- 连环画随真实扫描阶段逐格点亮。
- 显示当前检查类别，例如服务、启动项、计划任务和进程。
- 不伪造百分比；只有存在可靠总量时才显示确定进度。
- 扫描失败时保留已经获得的诊断信息，但不把不完整结果包装为完整结论。

### Results：先讲结论

- 使用普通语言总结，例如“发现 2 项可以安全处理，另外 4 项建议观察”。
- 明确提示“目前尚未修改任何内容”。
- 可处理项与观察项分组展示。
- 观察项不能使用“故障、危险、必须修复”等误导性标签。
- 主操作为“查看处理建议”。

### Review：确认边界

- 只有经过现有安全逻辑认定可执行的项目可以勾选。
- `exact`/`path` 的实际 matcher 命中可进入处理候选；`contains`/`regex` 命中只能进入只读观察区。
- 默认勾选仅限安全、已测试且拥有完整 matcher provenance 的候选项。
- 管理员授权、备份和恢复说明紧邻执行按钮。
- 展开技术详情后显示目标、action、`matched_pattern`、`matched_type`、`matched_field`、风险原因和证据。
- UI 勾选只是用户意图，不构成最终执行授权。

### Executing：逐项兑现

- 逐项显示等待、执行中、成功、失败和已跳过。
- 不以一个整体成功动画掩盖部分失败。
- 提权后的核心逻辑继续重新验证同一规则、matcher、字段和当前目标身份。
- 用户取消或授权失败时，未执行项目必须保持未修改状态。

### Completed：幻想落地

- 总结成功、失败和跳过数量。
- 对部分成功使用准确表述，不显示全量成功庆祝。
- 主要后续操作为“重新扫描”；恢复入口保持明显可见。
- 展开日志可查看每项的实际执行结果和失败原因。

### Error：幻想被打断

- 可以使用“鼠鼠的幻想被打断了”作为情绪化标题。
- 同屏给出真实错误摘要、发生阶段和是否已产生系统修改。
- 提供“重试”和“查看技术详情”。
- 不显示虚假成功，不吞掉失败项，不用无限加载代替错误反馈。

## 安全与数据边界

WPF 只负责状态呈现、选择收集和结果展示。扫描、pending 生成、提权授权、身份复核、执行、备份和恢复继续由现有核心脚本负责。

UI 必须消费核心层给出的有效 action 和 observation 分类，不得依据名称或厂商自行推断某项是否安全。显示对象至少保留：

- 规则 ID 和命中类别；
- 实际目标身份；
- 声明 action 与有效 action；
- `matched_pattern`、`matched_type`、`matched_field`；
- `safe`、测试证据与禁止执行原因；
- 当前状态和逐项结果。

安全不变量：

1. 宽匹配可以识别，但不能执行危险操作。
2. UI 不得用 `allow_auto` 或同一 profile 中其他窄 matcher 扩大授权。
3. pending v2 与完整 matcher provenance 缺失时要求重新扫描。
4. 提权进程必须用同一 matcher 和字段复核当前对象。
5. 文件、注册表、服务和计划任务的现有身份保护不因 UI 改版而绕过。

## 页面组件

单页由以下区域组成：

1. **应用顶栏**：产品名、当前权限状态、帮助和日志入口。
2. **四格幻想连环画**：固定阶段叙事与进度反馈。
3. **状态摘要区**：一句主结论、一句边界说明。
4. **主工作区**：扫描状态、结果分组、复核列表或逐项执行状态。
5. **折叠技术详情**：matcher provenance、目标字段、日志与证据。
6. **固定操作区**：每个状态唯一主操作，以及必要的取消、返回或恢复入口。

核心组件应根据现有 WPF 能力实现并复用：状态标题、计数徽标、结果行、只读观察行、详情折叠器、状态图标、主按钮、次按钮和行级执行结果。图片是可替换资源；资源缺失时，文字和核心操作仍须完整可用。

## 视觉系统

- 背景：暖奶油色，降低长时间阅读疲劳。
- 主强调色：幻想黄，用于当前阶段和唯一主操作。
- 文本与结构：深黑或炭灰，形成可靠工具感。
- 风险色：克制红色，仅用于真实危险、失败或不可逆警告。
- 成功色：低饱和绿色，不覆盖部分失败信息。
- 不采用蓝紫渐变科技风、玻璃拟态或过度发光效果。
- 鼠鼠素材保留对称 P 图、轻微低清和荒诞幻想感；不得拉伸、裁掉主体或用 CSS/Emoji 仿造。
- 功能图标使用统一的正规图标资源，鼠鼠图片不承担按钮识别职责。
- 动效仅用于阶段点亮、列表状态变化和折叠展开，并尊重减少动态效果的系统偏好。

## 文案规则

- 主标题先讲真实结果，例如“鼠鼠发现 2 项可以安全处理”。
- 副标题解释边界，例如“另外 4 项只供观察，不会自动执行”。
- 使用“扫描、建议、观察、处理、恢复”，避免“深度净化、极速优化、一键修复全部”。
- 不把未知、可疑或宽匹配项描述成系统故障。
- 权限请求说明为什么需要管理员权限以及接下来会发生什么。
- 错误文案同时包含鼠鼠语气和可操作的技术解释。

## 可访问性与窗口适配

- 文字、图标和背景达到清晰对比，状态不能只依赖颜色。
- 键盘可完成扫描、列表选择、详情展开、确认和取消。
- 焦点顺序与视觉流程一致，焦点样式清楚可见。
- 主要文字不嵌入图片；系统缩放后仍可读。
- 最小支持当前应用既有窗口下限，并验证 100%、125% 和 150% Windows 缩放。
- 列表内容过长时由工作区滚动，固定操作区不能遮住最后一项。

## 测试与验收

### 自动验证

- 现有 212 项 Pester 安全测试、旧逻辑、旧 Schema、GUI STA、AST、JSON 和 PSScriptAnalyzer 检查保持通过。
- 新增 UI 状态转换与每个状态按钮权限测试。
- 新增宽匹配只读、窄匹配可候选、缺失 provenance 禁止执行测试。
- 新增部分失败、取消、提权失败和错误恢复测试。
- 自动测试不得执行真实服务、计划任务、生产 Run 键或真实清理操作。

### 运行验收

- 普通权限和管理员权限分别走通完整旅程。
- 扫描和展示使用安全测试夹具或已控制环境；危险系统修改保持模拟。
- UI 展示计数、分类和逐项状态必须与 pending/结果对象一致。

### 视觉验收

- 对 idle、scanning、results、review、executing、completed 和 error 分别截图。
- 检查鼠鼠素材裁切、文字换行、间距、按钮层级、滚动和折叠详情。
- 在 100%、125% 和 150% 缩放下检查无遮挡、无截断。
- 将实现截图与选定“幻想连环画”视觉目标并排比较后再判断完成度。

## 非目标

- 不重写清理引擎或更改 Schema 3.0 profile 语义。
- 不重新放宽自动执行策略。
- 不在本阶段向 GitHub 推送或发布安装包。
- 不把四格连环画扩展为独立页面或复杂导航。
- 不以真实危险清理作为自动化验收手段。

## 完成标准

设计完成后的应用应让普通用户在一个页面中理解“正在检查什么、哪些能安全处理、哪些只能观察、系统是否已经被修改以及如何恢复”，同时让高级用户能够展开查看完整 matcher provenance 和执行日志。视觉应一眼能认出“鼠鼠的幻想”，但任何梗、动效或图片都不能掩盖安全边界与真实结果。
